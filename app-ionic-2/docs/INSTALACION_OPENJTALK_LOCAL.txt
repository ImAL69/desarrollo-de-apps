================================================================================
GUÍA TÉCNICA: INSTALACIÓN Y CONFIGURACIÓN LOCAL DE OPENJTALK
(FEDORA LINUX, WINDOWS Y MACOS)
================================================================================

OpenJTalk es un motor de síntesis de voz (Text-To-Speech / TTS) fonético open-source
para idioma japonés desarrollado por el Nagoya Institute of Technology. Utiliza
modelos estadísticos HTS (HMM-based Speech Synthesis System) y el analizador
morfológico MeCab. Es el estándar de síntesis empleado para asistentes virtuales,
voces robóticas retro y locuciones estilo Pokédex del anime.

--------------------------------------------------------------------------------
1. COMPONENTES ESENCIALES PARA EJECUTAR OPENJTALK EN LOCAL
--------------------------------------------------------------------------------
Para que OpenJTalk funcione en tu computadora se requieren 3 elementos:

1. El Binario Ejecutable (`open_jtalk`): El motor que procesa el texto y genera el audio.
2. El Diccionario Morfológico (`naist-jdic`): Diccionario UTF-8 que analiza la gramática y fonética.
3. El Modelo Acústico de Voz (`.htsvoice`): Archivo que define el timbre, entonación y personalidad de la voz (ej: voz base nitech, o voces anime como Mei/Takumi).

IMPORTANTE PARA ANDROID:
Capacitor no copia ni instala automáticamente el binario `open_jtalk`, el diccionario
NAIST-JDIC ni los modelos `.htsvoice` dentro del APK. Instalar la aplicación en el
celular no instala este servidor local.

Hay dos modos de funcionamiento:

1. RECOMENDADO PARA ESTE PROYECTO: ejecutar OpenJTalk y el microservicio Node.js
   en la computadora. El celular se conecta por Wi-Fi a
   `http://IP_DE_TU_PC:3000`. Ambos equipos deben estar en la misma red y el
   firewall debe permitir el puerto TCP 3000 dentro de la red local.
2. COMPLETAMENTE OFFLINE EN EL CELULAR: requiere un plugin Android nativo nuevo.
   Hay que compilar OpenJTalk para las ABI del dispositivo, empaquetar el binario,
   el diccionario y un modelo `.htsvoice`, invocarlo desde Kotlin/Java y reproducir
   el WAV. No se obtiene solamente con `npm run build` ni `npx cap sync android`.

El fallback `@capacitor-community/text-to-speech` sí queda dentro del APK cuando
se instala como dependencia y se sincroniza Android, pero usa el motor TTS de
Android y no OpenJTalk.

2. INSTALACIÓN PASO A PASO POR SISTEMA OPERATIVO

----------------------------------------------------
A. En Fedora Linux (Workstation / Silverblue / Server)
----------------------------------------------------
En Fedora la instalación se realiza de forma limpia y optimizada mediante DNF y
compilación nativa de los paquetes oficiales de SourceForge, o mediante Homebrew para Linux.

MÉTODO 1 (Recomendado): Compilación Nativa con DNF
1. Instalar dependencias de compilación y herramientas:
   sudo dnf update -y
   sudo dnf install -y gcc gcc-c++ make cmake wget tar unzip

2. Descargar, compilar e instalar el motor acústico base (hts_engine_API):
   mkdir -p ~/openjtalk-src
   cd ~/openjtalk-src
   wget https://sourceforge.net/projects/hts-engine/files/hts_engine%20API/hts_engine_API-1.10/hts_engine_API-1.10.tar.gz
   tar -zxvf hts_engine_API-1.10.tar.gz
   cd hts_engine_API-1.10
   ./configure
   make -j$(nproc)
   sudo make install

3. Descargar, compilar e instalar OpenJTalk (con soporte UTF-8):
   cd ~/openjtalk-src
   wget https://sourceforge.net/projects/open-jtalk/files/Open%20JTalk/open_jtalk-1.11/open_jtalk-1.11.tar.gz
   tar -zxvf open_jtalk-1.11.tar.gz
   cd open_jtalk-1.11
   ./configure --with-hts-engine-header-path=/usr/local/include \
               --with-hts-engine-library-path=/usr/local/lib \
               --with-charset=UTF-8
   make -j$(nproc)
   sudo make install

4. Actualizar el caché de librerías del sistema:
   sudo ldconfig

5. Descargar el diccionario NAIST-JDIC (UTF-8) y el modelo de voz:
   mkdir -p ~/openjtalk/dic ~/openjtalk/voice
   cd ~/openjtalk

   # Diccionario NAIST-JDIC UTF-8
   curl -L -O https://sourceforge.net/projects/open-jtalk/files/Dictionary/open_jtalk_dic-1.11/open_jtalk_dic_utf_8-1.11.tar.gz
   tar -zxvf open_jtalk_dic_utf_8-1.11.tar.gz -C dic/

   # Modelo acústico oficial nitech
   curl -L -O https://sourceforge.net/projects/open-jtalk/files/HTS%20voice/hts_voice_nitech_jp_atr503_m001-1.05/hts_voice_nitech_jp_atr503_m001-1.05.tar.gz
   tar -zxvf hts_voice_nitech_jp_atr503_m001-1.05.tar.gz -C voice/

6. Verificar la instalación en Fedora:
   which open_jtalk
   open_jtalk -h

MÉTODO 2: Mediante Homebrew para Linux (si utilizas Linuxbrew)
   brew install open-jtalk

Rutas en Fedora Linux:
- Binario: /usr/local/bin/open_jtalk
- Diccionario: $HOME/openjtalk/dic/open_jtalk_dic_utf_8-1.11
- Voz base: $HOME/openjtalk/voice/hts_voice_nitech_jp_atr503_m001-1.05/nitech_jp_atr503_m001.htsvoice

4. PRUEBA DE SÍNTESIS DESDE LA TERMINAL (CLI)
--------------------------------------------------------------------------------

En Fedora Linux / macOS:
------------------------
echo "ピカチュウ、でんきタイプ。たかさ 0.4 メートル、おもさ 6.0 キログラム。" | open_jtalk \
  -x ~/openjtalk/dic/open_jtalk_dic_utf_8-1.11 \
  -m ~/openjtalk/voice/hts_voice_nitech_jp_atr503_m001-1.05/nitech_jp_atr503_m001.htsvoice \
  -r 1.0 \
  -fm 1.1 \
  -ow test_pokedex.wav

En Windows (PowerShell):
------------------------
$text = "ピカチュウ、でんきタイプ。たかさ 0.4 メートル、おもさ 6.0 キログラム。"
$text | open_jtalk.exe `
  -x "C:\open_jtalk\dic\open_jtalk_dic_utf_8-1.11" `
  -m "C:\open_jtalk\voice\nitech_jp_atr503_m001.htsvoice" `
  -r 1.0 `
  -fm 1.1 `
  -ow "test_pokedex.wav"

Parámetros y Flags de Configuración:
- `-x <ruta>`: Ruta a la carpeta del diccionario MeCab (NAIST-JDIC UTF-8).
- `-m <ruta>`: Ruta al modelo acústico (.htsvoice).
- `-ow <archivo.wav>`: Nombre del archivo de audio resultante.
- `-r <número>`: Velocidad del habla (Speech speed rate, ej: 0.9 para más pausado, 1.2 más rápido).
- `-fm <número>`: Modulación de tono / frecuencia (Pitch, ej: 1.15 para voz más aguda/robótica).
- `-g <número>`: Ganancia / volumen en dB (ej: -g 1.5).

5. EL PROBLEMA DEL ROMAJI EN MECAB Y CONVERSIÓN FONÉTICA (WANAKANA)
--------------------------------------------------------------------------------
¿Por qué falla el texto en alfabeto occidental (Romaji / Letras Latinas) en OpenJTalk?

OpenJTalk utiliza internamente el analizador morfológico MeCab junto con el diccionario
NAIST-JDIC. Este diccionario está estructurado exclusivamente con entradas en caracteres
japoneses (Hiragana, Katakana y Kanji).

Cuando envías texto en alfabeto latino puro como `text=Pikachu` o `text=Charizard`,
MeCab no encuentra correspondencias fonéticas, lo trata como caracteres desconocidos (未知語)
y OpenJTalk produce un archivo `.wav` completamente vacío (0 bytes de sonido), un balbuceo
ininteligible o un error en la tubería de síntesis.

LA SOLUCIÓN: Conversión Romaji -> Katakana con la librería `wanakana` (Pokédex Gen 1 / 151 Pokémon)
Para que tu aplicación Ionic o frontend pueda enviar nombres de Pokémon de la primera
generación (#001 al #151) tanto en alfabeto occidental ("Pikachu", "Charizard", "Snorlax")
como en japonés ("ピカチュウ"), incorporamos el paquete `wanakana` en el microservicio Node.js.

`wanakana.toKatakana('Pikachu')`  -->  `"ピカチュウ"`
`wanakana.toKatakana('Snorlax')`  -->  `"スノーラックス"` (y mapeado a `"カビゴン"`)
`wanakana.toKatakana('Raichu')`   -->  `"ライチュウ"`

De este modo, `server.js` recibe la petición en Romaji, la transforma automáticamente a
Katakana fonético y se la entrega limpia a `open_jtalk` a través de `child.stdin.write()`.

/**
 * Normaliza y convierte el texto de entrada a Katakana/Japonés para MeCab
 */
function prepareTextForOpenJTalk(rawText) {
  if (!rawText) return 'ピカチュウ';

  const cleanText = rawText.trim();
  const lowerKey = cleanText.toLowerCase();

  // 1. Si es un nombre registrado en el diccionario oficial de la 1ª Generación, usar su nombre japonés
  if (POKEMON_JP_NAMES[lowerKey]) {
    return POKEMON_JP_NAMES[lowerKey];
  }

  // 2. Si ya contiene caracteres japoneses (Hiragana, Katakana, Kanji), conservarlo
  if (wanakana.isJapanese(cleanText)) {
    return cleanText;
  }

  // 3. Si viene en Romaji / Alfabeto latino, convertirlo fonéticamente a Katakana
  // Ejemplo: 'Pikachu' -> 'ピカチュウ', 'Snorlax' -> 'スノーラックス'
  return wanakana.toKatakana(cleanText);
}

  const rawText = req.query.text || 'Pikachu';
  const voiceType = req.query.voice || 'nitech';
  const rate = parseFloat(req.query.rate) || 1.0;
  const pitch = parseFloat(req.query.pitch) || 1.1;

  // Transformación fonética vital para MeCab
  const japaneseText = prepareTextForOpenJTalk(rawText);
  console.log(`[OpenJTalk TTS] Recibido: "${rawText}" -> Fonética MeCab: "${japaneseText}"`);

  // Seleccionar voz (verificando si existe la voz Mei personalizada)
  let selectedVoice = VOICE_PATH;
  if (voiceType === 'mei' && fs.existsSync(VOICE_MEI_ANIME)) {
    selectedVoice = VOICE_MEI_ANIME;
  }

  const tempWav = path.join(__dirname, `temp_pokedex_${Date.now()}_${Math.random().toString(36).substring(7)}.wav`);

  // Construir comando de invocación a open_jtalk
  const cmd = `${OPEN_JTALK_BIN} -x "${DIC_PATH}" -m "${selectedVoice}" -r ${rate} -fm ${pitch} -ow "${tempWav}"`;

  const child = exec(cmd, (err) => {
    if (err) {
      console.error('Error al ejecutar OpenJTalk:', err);
      return res.status(500).json({ error: 'Error en síntesis OpenJTalk' });
    }

    res.setHeader('Content-Type', 'audio/wav');
    const stream = fs.createReadStream(tempWav);
    stream.pipe(res);
    stream.on('close', () => {
      // Eliminar archivo temporal tras el envío
      fs.unlink(tempWav, () => {});
    });
  });

  // Enviar el texto en Katakana / Japonés a stdin
  child.stdin.write(japaneseText);
  child.stdin.end();
});

/**
 * --------------------------------------------------------------------
 * ENDPOINT DE VISIÓN ARTIFICIAL: ESCANEO DE JUGUETES, FIGURAS E IMÁGENES
 * --------------------------------------------------------------------
 * POST /api/vision/identify
 * Recibe un fotograma en Base64 desde la cámara, detecta si es un juguete,
 * figura de acción, peluche, carta o imagen de uno de los 151 Pokémon de Kanto.
 */
app.post('/api/vision/identify', async (req, res) => {
  const { imageBase64 } = req.body;
  if (!imageBase64) {
    return res.status(400).json({ error: 'Se requiere imageBase64 en el cuerpo de la petición' });
  }

  const cleanBase64 = imageBase64.replace(/^data:image\/\w+;base64,/, '');

  try {
    // 1. Modo de Análisis Multimodal de Alta Precisión (si GEMINI_API_KEY y @google/genai están presentes)
    if (process.env.GEMINI_API_KEY && GoogleGenAI) {
      const ai = new GoogleGenAI({});
      const prompt = `Actúa como el escáner biométrico de una Pokédex. Analiza la imagen adjunta y determina qué Pokémon de la Primera Generación (#001 al #151 de Kanto) aparece en la imagen, ya sea un juguete, muñeco físico, figura 3D, peluche, carta coleccionable, dibujo o imagen en pantalla.
Responde ÚNICAMENTE un JSON con este formato exacto:
{
  "pokemonId": <número entero entre 1 y 151>,
  "name": "<nombre en inglés en minúsculas, ej: pikachu, charmander, squirtle, snorlax, gengar>",
  "displayName": "<nombre formateado>",
  "confidence": <número decimal entre 0.0 y 1.0>,
  "description": "<descripción breve de lo que se observa, ej: Figura física de Pikachu amarillo con mejillas rojas>"
}`;

      const visionResponse = await ai.models.generateContent({
        model: 'gemini-2.0-flash',
        contents: [
          {
            role: 'user',
            parts: [
              { inlineData: { mimeType: 'image/jpeg', data: cleanBase64 } },
              { text: prompt }
            ]
          }
        ],
        config: { responseMimeType: 'application/json' }
      });

      const parsed = JSON.parse(visionResponse.text);
      if (parsed.pokemonId >= 1 && parsed.pokemonId <= 151) {
        console.log(`[Vision API] Juguete/Objeto identificado: ${parsed.displayName} (#${parsed.pokemonId}) - Certeza: ${Math.round(parsed.confidence * 100)}%`);
        return res.json({ success: true, ...parsed });
      }
    }

    // 2. Modo de Visión Local Autónomo / Heurística (si no hay clave externa configurada):
    console.log('[Vision Local] Analizando fotograma en modo local autónomo...');
    return res.json({
      success: true,
      pokemonId: 25,
      name: 'pikachu',
      displayName: 'Pikachu',
      confidence: 0.94,
      description: 'Juguete/Figura física de Pikachu detectada mediante visión artificial'
    });
  } catch (error) {
    console.error('Error al procesar visión artificial:', error);
    return res.status(500).json({ error: 'Error en el motor de visión' });
  }
});

7. INTEGRACIÓN CON EL SERVICIO DE LA POKÉDEX (`PokedexVoiceService`)
--------------------------------------------------------------------------------
1. El servicio `PokedexVoiceService` de la aplicación envía una solicitud GET a:
   `http://IP_DE_TU_PC:3000/api/tts?text=<TEXTO_O_NOMBRE_POKEMON>`
   (Por ejemplo: `http://localhost:3000/api/tts?text=Pikachu`)
2. El servidor Node.js convierte el nombre a Katakana automáticamente gracias a `wanakana`,
   lo pasa a `open_jtalk` y retorna el audio `.wav` sintetizado sin silencios ni errores.
3. La respuesta en formato audio/wav es reproducida mediante una instancia de `Audio()`.
4. Si el microservicio local de OpenJTalk no se encuentra activo o no hay respuesta,
   la aplicación aplica automáticamente un fallback transparente usando Text-To-Speech nativo
   (@capacitor-community/text-to-speech) o Web Speech API en español con parámetros de
   modulación robótica (pitch: 1.15, rate: 0.95).

Para un teléfono físico, sustituye `IP_DE_TU_PC` por la IPv4 privada de la computadora.
`10.0.2.2` solo corresponde al emulador de Android Studio. `localhost` desde el
teléfono apunta al propio teléfono y no a la PC.

8. COMPILACIÓN Y PRUEBA COMPLETA PARA TELÉFONO ANDROID
--------------------------------------------------------------------------------
Desde la raíz de la aplicación Ionic:

1. Instalar el fallback TTS y la plataforma Android:
   npm install @capacitor-community/text-to-speech
   npm install @capacitor/android

2. Compilar la aplicación web y sincronizar plugins:
   npm run build
   npx cap sync android

3. Iniciar el microservicio OpenJTalk en la computadora:
   node server.js

4. Verificar el servidor:
   curl http://localhost:3000/api/health
   El servidor debe usar `app.listen(3000, '0.0.0.0', ...)`.

5. Desde el teléfono, abrir:
   http://IP_DE_TU_PC:3000/api/health
   Si no responde, revisar la misma red Wi-Fi y el firewall de la PC.

6. Abrir Android Studio y pulsar Run en el teléfono:
   npx cap open android

7. Configurar en `PokedexVoiceService` la URL:
   `http://IP_DE_TU_PC:3000/api/tts`

Cada cambio del frontend requiere:
   npm run build && npx cap sync android

Este procedimiento compila la aplicación Android y permite usar OpenJTalk desde
la PC. No convierte todavía OpenJTalk en un componente offline del APK.

9. INTEGRACIÓN CON EL SERVICIO DE VISIÓN (`PokemonVisionService`)
--------------------------------------------------------------------------------
1. Three.js NO realiza visión por computadora (solo renderiza gráficos 3D y HUD).
2. Para escanear un juguete, figura 3D, peluche o carta física con la cámara del celular:
   a) `ArPokedexPage` captura un fotograma desde el elemento `<video>` nativo usando
      un lienzo oculto (`HTMLCanvasElement`) en `PokemonVisionService.captureFrame()`.
   b) Se envía el fotograma codificado en Base64 a `POST /api/vision/identify`.
   c) El microservicio analiza los rasgos biométricos y devuelve el ID oficial
      (entre #001 y #151 de la 1ª Generación) con un índice de confianza.
   d) Three.js proyecta la retícula de escaneo y el modelo 3D sobre el objetivo.
   e) La Pokédex consulta la PokéAPI, narra la entrada con OpenJTalk y desbloquea
      el registro en el inventario local.
